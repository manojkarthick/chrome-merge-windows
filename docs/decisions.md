# Design decisions and API evidence

The product decisions are immediate toolbar merging of all normal windows in the same profile/mode, including minimized sources; ascending source window ID order; retaining native tab groups; and rebuilding flattened source split pairs with `tabs.createSplit`. This requires Chrome 155 with no older-version fallback. Rebuilt pairs reset to side-by-side at 50/50; intact native group splits and destination splits are not rebuilt. Successful and no-op invocations show only a one-second tick. A details popup appears only for errors, including failed split rebuilds. The tooltip counts rebuilt pairs. No options page, skip outcome, preview, rollback, bridge, telemetry, or backend is needed.

The chosen strategy moves live tabs first, then rebuilds source pairs that separated. The alternative of moving splits through temporary tab groups was rejected because of its visible group-header flash and possible group-sync side effects. The accepted trade-off is losing the original layout/ratio when a rebuild is needed.

## Reuse assessment

The existing prototype supplied useful ordering and sequential-failure ideas and an API-model fixture. Its twelve tests passed before adaptation. Its helper-page launch protocol, temporary tab, extension key, Raycast script, and AppleScript are not included. Transfer accounting now reads actual destinations, including when pin repair or part of a group transfer fails.

[Sindre Sorhus's Merge Windows](https://github.com/sindresorhus/merge-windows/blob/main/background.js) is a small existing implementation, but its bulk move and popup-window gathering do not meet these requirements. Group preservation, original active-tab restoration, and detailed failure feedback would need to be added. [Tab Reunion](https://flaviocopes.com/tab-reunion/) describes a much closer native-group implementation, but its source could not be fetched during research, so split and failure behavior could not be verified. [Merge All Windows](https://github.com/adrianlshaw/merge-all-windows) explicitly removes source windows and chooses a different destination. None was a verified drop-in solution. Chrome already provides the needed APIs; a runtime library would add little value.

## Current official references

- [Windows API](https://developer.chrome.com/docs/extensions/reference/api/windows): service workers' current window can fall back to last active. Use the explicit window ID supplied by the toolbar action's clicked tab.
- [Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs): basic moves and updates do not require `tabs` or host permissions. Sensitive properties are separately protected. `tabs.createSplit`, available from Chrome 155, pairs exactly two adjacent, unsplit tabs with matching window, pinned, and group state. Preserving tab order and pins keeps each source pair eligible for rebuilding.
- [Tab Groups API](https://developer.chrome.com/docs/extensions/reference/api/tabGroups): `tabGroups.move` moves the group and its live members between normal windows and requires `tabGroups`. Native moves avoid flattening/recreating groups.
- [Split View API](https://developer.chrome.com/blog/split-view-api-extensions): reconstruction methods arrive in Chrome 155. They do not expose original layout proportions. [Chromium split-move tests](https://chromium.googlesource.com/chromium/src/+/25e6f1fd89b7cd0285e6b529ddc356055d711781/chrome/browser/extensions/api/tabs/tabs_test.cc) demonstrate that a single-tab move can dissolve a split. Source pairs are restored when necessary and checked after rebuilding; their new split ID need not match the original. Destination split IDs must remain unchanged.
- [Incognito manifest](https://developer.chrome.com/docs/extensions/reference/manifest/incognito): `split` provides separate regular/private extension contexts after user enablement. The explicit mode filter adds an easy-to-audit boundary.
- [Action API](https://developer.chrome.com/docs/extensions/reference/api/action): `onClicked` starts the merge with the invocation tab. The worker opens a popup only for errors, temporarily configuring its document before `openPopup({windowId})` and clearing the setting afterward so future clicks still invoke the handler. The badge and accessible title retain feedback if details cannot open. A permission-free short timer clears the success badge after one second.
- [Chromium tab implementation](https://chromium.googlesource.com/chromium/src/+/2647139922107a62ff85b1d3eb3d2e9d88e51eb1/chrome/browser/extensions/api/tabs/tabs_api.cc): bulk moves iterate through tab IDs and may partially complete. The extension moves ordinary tabs sequentially and counts a rejected group operation by readback.

The implementation deliberately relies on browser profile scoping rather than inventing a profile identifier or scanning other profiles. The profile boundary test double models that browser contract; a separate live browser profile supplies additional isolation evidence.
